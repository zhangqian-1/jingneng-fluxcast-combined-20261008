# 异常值处理与工作日志

更新日期：2026-09-19。本文为当前生效规则，替代此前“所有数值异常直接拒绝”的说明。

## 处理规则

适用于平台实时燃机测点，以及原始长表、随包文件和旧HTTP宽表入口的新能源预测。

1. 缺失值、null、NaN、无穷大、非法类型或负数，优先沿用同一测点/场站上一有效时段的值。新能源超过已配置容量的值按同一规则处理。
2. 连续异常持续沿用最近有效值，日志保留真正有效值的来源时刻；新有效值出现后立即恢复使用。0是有效值，不能当缺失值处理。
3. 不借用其他场站或测点，不用后一个时刻反向填充，不修改原始预测文件或请求。
4. 新能源首点超容量且无前值时，使用该场站配置容量上限，记录 `initial_capacity_limit`；后续异常优先沿用上一有效值。原始新能源长表含同批次前一个15分钟有效点时，仍优先沿用该点。首点空值、缺失、负数或非有限值不能用容量代替。
5. 必要输入没有可用前值、也不满足首点超容量条件时，实时接口返回HTTP200、`status=unavailable`，当前请求站96点的 `value` 全部为JSON `null`，并标记 `metadata.dispatch_valid=false`。不会启动缺少必要输入的七站联合优化。同批次其他站也不会拿到有效指令或旧缓存结果；异常状态保存在SQLite中，数据补齐后才能恢复。
6. 时间轴错误、未知场站、重复时间、批次混合、上游连接失败、求解失败仍明确报错。上一时刻替代只处理可定位的数值异常，不替代结构校验或优化求解。
7. 历史CSV离线情景保留原有清洗口径，不将本次实时处理规则套到历史基准上。离线新能源预测使用新规则。

有限的历史值可以支持延续计算，不代表补出的数值是真实测量或新预测。当前连续异常没有额外时长阈值；日志逐点记录其来源时间，接口明确标记替代状态。

## 接口返回

七站完成响应的 `metadata.input_quality` 示例：

```json
{
  "policy": "previous_valid_first_capacity_or_null_v3",
  "status": "substituted",
  "renewable_replacements": 2,
  "thermal_replacements": 1
}
```

`original` 表示输入没有发生替代。计数为七站当前输入中的替代点数，不累加重试次数。替代依据参与输入哈希，避免替代输入与原始有效输入被视为同一份数据；处理策略也参与聚合批次标识，避免沿用升级前缓存。

## 日志位置及字段

默认：`output/logs/work.jsonl`。可由 `WORK_LOG_PATH` 指定。UTF-8格式，一行一个JSON对象，追加写入。

输入处理记录包含：

- `logged_at`：记录时间，UTC且带时区。
- `policy`：处理策略版本。
- `series`、`station`或`forecast_batch`：测点、场站或新能源批次。
- `timestamp`：异常时段的开始时间，实时输入归一到UTC且带时区。
- `original_value`、`reason`：原值及原因；NaN/无穷大以字符串记录，日志保持合法JSON。
- `action`：`carry_forward`为沿用，`null_no_previous`为无前值空结果，`initial_capacity_limit`为首点按装机上限计算。
- `replacement_value`、`source_timestamp`：替代值及最近有效值来源时间。

求解日志记录 `started/completed/failed`，包含唯一 `run_id`、负荷日期、新能源日期和求解器。平台请求日志记录等待、求解中、完成或拒绝，包含 `source_id`、调度 `batch_key` 和处理结果。重试请求独立留痕；输入处理成功日志不代表整次调度成功。

日志无法写入时不能无记录地继续；实时接口返回503 `WORK_LOG_UNAVAILABLE`。离线求解通过原有503失败响应报告日志或执行失败。若一个请求本身已被拒绝，则保留原拒绝响应，同时把日志写入失败记到服务日志。

## 平台必须识别的空结果

```json
{
  "source_id": 5,
  "status": "unavailable",
  "result_point": [{"varname":"GARD_MW","timestamp":"2026-09-19 00:00:00","value":null,"period":1}],
  "metadata": {"dispatch_valid":false,"reason_code":"INPUT_VALUE_UNAVAILABLE"}
}
```

这里只展示一条结果；实际返回96条，并含 `event_key`、`batch_key` 和 `input_issues` 详细原因。HTTP200只表示请求已处理，平台必须检查 `status` 与 `dispatch_valid`，不得把 `null` 转为0、不得将 `unavailable` 当作完成指令。成功响应的数值schema仍不接受null；空结果使用单独schema。日志写入失败仍为503；时间轴、结构和批次冲突仍保持原错误状态。

离线 `/compute` 和CLI没有逐站空结果契约；它们会对无前值必要输入终止计算并记录原因，不生成伪造计算结果。

## 预测批次（报告第三项）如何确定

向预测系统维护方确认：批次列表或最新批次查询接口、实际发布时刻及其时区、发布延迟、批次是否会修订，以及每批预测覆盖范围。202609180800只是本附件的一个批次，不能单凭它认定每天固定08:00发布。

确认后由平台在调度截止时间前选取最新可用且覆盖目标调度日的完整批次，19场站使用同一批次。是否允许改用上一发布批次、可接受的最旧批次和告警流程，应由业务方明确。即使改用上一批次，也必须按目标日期取96点，不能固定取timeSeries=1。本封装负责验证所收到的批次及日期，不负责猜测批次号，也尚未实现主动轮询或自动抓取上一发布批次。

首日上限规则实跑：2026-09-19预测首点157.955 MW采用150.8 MW，原始数据不改写。实际HiGHS求解通过，结果位于 `output/first-day-capacity-check/`，已同步到本地 `output/final/` 和随包看板。默认离线新能源日期已调整为2026-09-19。
