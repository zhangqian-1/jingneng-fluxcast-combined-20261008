# 全场站接口变更与验证记录（2026-09-20）

## 采用的约定

依据用户提供的《fluxcast平台对接接口约定修改.md》，并按用户明确确认：成功结果只含浮点数，无法计算返回错误；无时区时间按UTC解释。新公共入口完整执行全场站协议，不保留带source_id的逐站调用方式。

- 路由仍为POST /api/v1/fluxcast/compute；监听端口未变。
- 一次请求携带七站全部测点的96帧和19场同一批次原始预测。
- 一次返回七站672个出力点及数值汇总，event_key固定JNH.Fluxcast.Compute。
- 时间按UTC校验，响应时间字符串保持与请求一致。
- 不返回旧period、source_id、pending、unavailable或null结果。
- 数值替代和首点上限规则继续记日志；无可用值返回422，求解失败返回503。
- 新路由不使用SQLite七站等待、旧缓存或默认文件预测兜底；每次请求完整校验、独立求解和保存。同日数据修订可以重新提交完整请求。

文档中的两处历史表述按整体约定处理：逐站发送改为全站单次发送；固定timeSeries=1改为按frames实际时刻取96点。原因是UTC自然日跨越预测表的两个北京时间日期，固定首日会丢失或错配时段。原生predictedTime继续按北京时间结束时刻处理，仅转换一次。
