# 新能源数据来源确认（2026-09-27）

按对接方最新要求：新能源场站功率预测统一从请求约定中的renewable_data字段读取，算法不要主动发请求。该要求与第一份[平台接口MD](requirements/platform-contract-20260919.md)一致。

## 数据来源与调用责任

| 数据 | 谁负责获取 | 算法使用方式 |
|---|---|---|
| 19个新能源场站预测 | 平台调用新能源系统，汇总19个data数组、选择batch | 只读本次renewable_data，不请求新能源系统 |
| 七站下一15分钟合计功率预测 | 包内单点预测服务 | 算法将point_table与frames传给该服务，取1点用于单时段优化 |
| 七站未来24小时合计功率预测 | 包内独立长预测服务 | 平台按需调用，输出96点，不参与优化 |

主平台入口仍为POST `/api/v1/fluxcast/compute`，只要求point_table、frames、renewable_data三个顶层字段。新能源原始长表字段、timeSeries=1、批次及容量校验、结束时间减15分钟和UTC对齐规则保持原约定。

FORECAST_BASE_URL配置的是七站单点预测服务；联合Compose默认http://forecast:8000。它不是新能源API地址。算法没有新能源URL配置或定时抓取任务，也不会在renewable_data缺失时转向网络、长预测服务或随包历史文件补数。

renewable_data缺失、为空、为null或缺场站时返回HTTP 422、固定event_key及空result_point，平台需补齐后重试。返回的新能源出力受本次传入并按既定规则校验后的预测约束。
