## 3. 验证记录

Windows与Linux各112项pytest通过；Ruff检查及格式检查通过，28项原始文件哈希和ARM依赖轮子检查通过。生产HTTP另验：健康200，非法JSON400，缺字段422，过期历史409，旧整日/滚动404，错误结果均为空数组。用真实原预测容器与新优化镜像验证原路径、三字段请求、预测点映射、HiGHS结果、29浮点输出及重试一致性。打包器强制比较源码、镜像和容器联调运行哈希。

隔离历史回放从北京时间2025-10-06开始，连续补传至10-30。首次空缓存前6批等待，第7批开始产生96点。末批历史末帧UTC2025-10-30 15:45，预测首点UTC16:00为 **1785.9304 MW**。

完整平台链路使用真实七站功率/天气历史，优化状态由这段历史推断。新能源使用19站全零长表测试情景。HTTP成功返回29点，功率平衡误差小于1e-5MW；本次objectiveYuan为234473.36815325066元，carbonTon为136.49615429006587吨。两者属于该测试情景，不代表现场实际收益。

此前2025-10-19样例的京桥功率通道首帧为null且无前值，平台适配层返回422空结果。该拒绝符合缺测规则；未修改原始记录，也未为通过测试补零。随后选择有合法初始观测的10-30历史完成成功验证。原始失败证据保存在本地独立验证目录；源码测试包含同类无前值拒绝用例。

完整输入输出见[样例说明](../examples/README.md)。原始预测96点、平台29点、回归详细结果、验证报告和运行哈希均随离线包附带。生产接口没有历史时钟覆盖；样例日期已过期，直接请求生产实例应被拒绝。

## 4. 尚需现场确认的事项

1. **康保容量**：配置150.8MW，上游报告首点157.955MW。代码能按现有策略限容并留痕，但无法仅据一次预测擅改装机容量。应由业务确认配置与预测口径。
2. **ARM部署**：当前原预测交付及本次联调为Linux/amd64。ARM依赖轮子可获得性检查通过不等于aarch64麒麟V10 SP3整包兼容、求解性能或预测性能验收；仍需目标镜像与实机测试。
3. **状态和约束**：原协议没有遥信、窗口之前完整启停记录。历史功率估计并非精确机组事件；场站最小开停机时间、爬坡、启停次数、购电上限及费用参数仍应由现场确认。不能把未知新能源实测写成零。
4. **预测批次回退**：第一份文档建议旧batch回退，同时要求timeSeries=1。这可能使首日不再覆盖当前目标日。本版本坚持timeSeries=1与时间一致性，不静默改用timeSeries=2；过期首日返回422。平台应提供能覆盖目标日的批次，跨日fallback仍需业务确定。
5. **预测就绪与真实数据质量**：新服务必须补足原模型历史；功率缺测可能让预测能运行而优化不能取得可信状态。优化返回空结果与原因，平台须识别，不能以HTTP可访问等同于业务就绪。
6. **现场联调**：本次是隔离容器及归档真实历史验证，新能源为测试情景。未连接生产平台、未执行现场控制，未测目标ARM服务器时延，不宣称完成生产上线验收。
