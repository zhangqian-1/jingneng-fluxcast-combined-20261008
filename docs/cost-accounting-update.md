# 成本口径升级：发电成本含燃料

本次按用户确认采用表中发电成本已含燃料费的假设，不更改七站参数数值、出力上下限、启停、爬坡和碳约束。HiGHS、Gurobi、离线基准/复现、逐时段核算和看板均取消额外气费。

总成本 = 含燃料发电成本 + 启停费 + 购电费 + 碳成本 + 弃电惩罚。

## 结果字段

| 字段 | 当前含义 | 是否计入总成本 |
|---|---|---|
| `directGenerationCostYuan` | 表中单位发电成本 × 发电量，已含燃料 | 是，仅一次 |
| `fuelCostYuan` | 兼容旧字段，等于上述发电成本，并非额外费用 | 不另加 |
| `naturalGasCostYuan` | 另行收费的天然气成本，固定为 0 | 无额外收费 |
| `estimatedNaturalGasCostYuan` | 气价 × 热耗率 ÷ 低位热值 × 发电量 | 否，仅参考 |
| `baselineEstimatedNaturalGasCostYuan` | 原始基准对应的参考气费估算 | 否 |
| `thermalModel.costBasis` | `generation_includes_fuel_v1` | 口径标识 |

相应单位成本字段 `naturalGasCostYuanPerKWh` 为 0，新字段 `estimatedNaturalGasCostYuanPerKWh` 为参考估算。看板不再把参考气费绘为成本构成，发电成本标注“含燃料”。平台输入结构和逐站96点输出结构不变。

实时接口在 `metadata.cost_basis` 标注成本版本，`metadata.global_kpis` 使用上述新口径；离线接口通过 `metadata.thermal_model.costBasis` 标注版本。看板接口顶层提供 `costBasis`。

这是用户批准的建模假设；工作簿没有明确拆分燃料、运维等费用。气价变化只影响参考估算，不再直接改变调度；不能用估算气费从综合成本中推导未经确认的非燃料成本。启停费、碳成本仍沿用既有独立核算，是否与经营成本重叠需资料方确认。

## 部署与结果更新

1. 更新代码后运行 `uv run pytest -q`。
2. 停止旧版本服务，统一更新全部进程；不要新旧版本混跑。
3. 用 `uv run python -m src.dispatch_engine --output-dir output/final` 重新求解；仅重新绘图不能修正旧调度或旧成本。
4. 运行 `uv run python scripts/export_dashboard.py --result-dir output/final` 更新随包展示数据。若配置其他 `DASHBOARD_RESULT_DIR`，该目录也须重算。旧口径结果返回503，不会静默展示为新结果。
5. 启动服务后，平台重新提交七站完整96点数据。批次键加入成本版本，同日新请求不会命中升级前的已完成结果；历史SQLite记录保留不删除。

成本节约率必须用同一新口径的基准与优化成本计算，不能将新结果与旧报告的总成本混合比较。本地完成修改和测试不代表远端GitLab流水线或生产部署已更新。
