# 价格参数配置接口约定（2026-09-29修订：14项）

本版按原《价格参数配置接口约定-20260929(1).md》修订。按用户最新要求去掉天然气价的可编辑字段，只保留七站发电成本、购电价共14项。算法侧已实现GET/PUT，线上是否生效取决于部署是否更新到本版，不能仅凭文档交付判断上线。

## 1. 用途与边界

平台编辑七站两个价格参数。原 `POST /api/v1/fluxcast/compute` 请求不变，价格不放在compute请求里。正常15分钟推送不需要增加调用。价格保存后，新建调度断面使用新版本；已存在断面、等待预测、计算中、重复请求和历史结果使用原绑定版本。

“去掉天然气价”指不在本配置接口中返回或接收 `gas_price_yuan_per_m3`，也不作为本次界面的可编辑项。算法已有内部参考估值参数保留，不重新计入成本合计，不改变既有目标函数。

## 2. 接口清单

| 路径 | 方法 | 用途 |
|---|---|---|
| /api/v1/fluxcast/config/prices | GET | 当前14项价格及版本 |
| /api/v1/fluxcast/config/prices | PUT | 全量保存14项价格 |

PUT使用Content-Type: application/json，GET无请求体。不接受查询参数，包括source_id。GET/PUT成功响应均为JSON并设置Cache-Control: no-store。使用优化服务原端口，默认18768；不是全天预测18780端口。

```json
{
  "version": 0,
  "updated_at": null,
  "stations": [
    {"code": "GARD", "gen_cost_yuan_per_kwh": 0.48, "buy_price_yuan_per_kwh": 0.615},
    {"code": "JFRD", "gen_cost_yuan_per_kwh": 0.5856, "buy_price_yuan_per_kwh": 0.614},
    {"code": "JQRD", "gen_cost_yuan_per_kwh": 0.635, "buy_price_yuan_per_kwh": 0.61},
    {"code": "JXRD", "gen_cost_yuan_per_kwh": 0.5223, "buy_price_yuan_per_kwh": 0.5354},
    {"code": "JYRD", "gen_cost_yuan_per_kwh": 0.5279, "buy_price_yuan_per_kwh": 0.5289},
    {"code": "SZRD", "gen_cost_yuan_per_kwh": 0.7, "buy_price_yuan_per_kwh": 0.61},
    {"code": "WLRD", "gen_cost_yuan_per_kwh": 0.63, "buy_price_yuan_per_kwh": 0.6}

```

七站返回顺序固定如上，平台按code匹配，不按界面行序猜测。首次初始化用部署包默认值建立持久化版本0，updated_at为null；首次实际修改后为服务端UTC ISO时间，例如2026-09-29T08:00:00Z。重新部署或重启不会自动覆盖已经保存的价格配置。

上述数值与当前封装配置一致，仅供联调核对，不表示市场实时价格。平台无需内置另一份默认价格。

## 4. PUT全量保存

在GET所得完整stations上修改后提交。顶层使用 `expected_version`，取读取时GET的version；不要原样提交GET的version或updated_at字段。

```json
{
  "expected_version": 0,
  "stations": [
    {"code": "GARD", "gen_cost_yuan_per_kwh": 0.52, "buy_price_yuan_per_kwh": 0.615},
    {"code": "JFRD", "gen_cost_yuan_per_kwh": 0.5856, "buy_price_yuan_per_kwh": 0.614},
    {"code": "JQRD", "gen_cost_yuan_per_kwh": 0.635, "buy_price_yuan_per_kwh": 0.61},
    {"code": "JXRD", "gen_cost_yuan_per_kwh": 0.5223, "buy_price_yuan_per_kwh": 0.5354},
    {"code": "JYRD", "gen_cost_yuan_per_kwh": 0.5279, "buy_price_yuan_per_kwh": 0.5289},
    {"code": "SZRD", "gen_cost_yuan_per_kwh": 0.7, "buy_price_yuan_per_kwh": 0.61},
    {"code": "WLRD", "gen_cost_yuan_per_kwh": 0.63, "buy_price_yuan_per_kwh": 0.6}
  ]
}
```

| 字段/规则 | 约束 |
|---|---|
| expected_version | 必填非负整数，不接受字符串、布尔值或小数类型 |
| stations | 恰好七站，全量提交，顺序可不同，响应会恢复固定顺序 |
| code | 七站代码之一，不得缺失、重复或增加未知站 |
| 每站价格 | 发电成本和购电价两项均必填，有限数值且大于0 |
| 拒绝值 | null、字符串、true/false、NaN、正负无穷、0、负数 |
| 未知字段 | 顶层或场站内均拒绝，包括gas_price_yuan_per_m3 |

校验、版本比较和整批写入在同一数据库事务中完成。任一错误整体不保存，不能出现部分电厂采用新价格。两项价格单位均为元/kWh，平台不要乘1000后提交。暂无业务确认的合理上限，不编造价格上限。

HTTP 200响应结构与GET相同，返回完整保存结果。实际改动时version增加1并更新updated_at；版本匹配但14项值完全相同时，返回原配置，不增加版本或改动更新时间。

## 5. 字段口径

| 字段 | 单位 | 当前算法用途 |
|---|---|---|
| gen_cost_yuan_per_kwh | 元/kWh | 按含燃料的单位发电成本进入优化目标和成本核算 |
| buy_price_yuan_per_kwh | 元/kWh | 按七站当前负荷占比加权，计算主网购电成本；不是七站分别独立优化购电量 |

原始收资表没有完整列明成本构成；“含燃料”是当前算法采用的口径，构成仍需业务确认。该口径下不重复叠加天然气参考估值。碳价、启停费用、弃电惩罚、售电价等不是本次价格编辑字段。

## 6. 生效与持久化

- 新建断面以算法数据库首次保存该断面输入并绑定价格版本的事务为准。
- PUT成功提交后的新断面读取新版本。保存前已存在的断面，包括还在等预测的断面，继续使用旧版本。
- 求解子进程使用该断面固定的完整价格快照，不在启动时另读最新价格。结果归档price_version及实际采用的机组参数，正式compute返回的30个数值点和extra_info契约不变。
- 多人修改同一版本时，只能有一次实际保存成功；另一请求返回409。平台提示重新加载，不能自动用旧表覆盖新值。
- 历史结果不重算。旧数据库升级时已有断面绑定初始化版本0，不用之后修改的价格追溯改写。
- 数据保存在SINGLE_PERIOD_DB_PATH指向的同一持久化数据库，单容器部署默认/app/runtime/single-period.sqlite3。无需重启或额外通知算法。
- PUT超时不能直接认定未保存；先GET核对当前完整价格和版本。旧expected_version重复提交返回409，不进行二次覆盖。

## 7. 异常

| HTTP | error_code | 含义 |
|---:|---|---|
| 400 | INVALID_JSON | 请求不是合法JSON |
| 422 | PRICE_VALIDATION_ERROR | 站点、字段、版本类型、数值或查询参数不合法 |
| 409 | PRICE_VERSION_CONFLICT | expected_version过期，需要重新读取核对 |
| 503 | PRICE_CONFIG_UNAVAILABLE | 配置存储、已有数据或价格操作日志不可用 |

一般错误返回 `{"error_code":"...","detail":"..."}`。409额外返回current_version：

```json
{
  "error_code": "PRICE_VERSION_CONFLICT",
  "detail": "价格配置已更新，请重新读取并核对后保存",
  "current_version": 1
}
```

价格接口不用event_key、result_point、extra_info；这些仍用于计算响应。

## 8. 平台对接与验收

平台后端负责鉴权、限制改价权限、记录操作人与修改前后值，并转发算法接口。浏览器不要直接暴露算法管理接口。页面打开时GET，保存成功后用PUT返回结果更新界面，409时重新加载供用户核对。正常计算仍按原15分钟流程调用，保存价格本身不触发额外compute。

需验证全量回显、14项映射和单位、拒绝天然气字段、非法值不部分保存、并发冲突、旧断面重试、新断面生效、数据库重启持久化。GET表示当前配置，不代表某一历史结果采用的价格版本。

## 9. 相比原MD的改动

1. 按用户最新要求，由21项改为14项，删除天然气价的请求、返回和默认值列。
2. 增加version、expected_version、updated_at及409冲突处理。
3. 将“下一个求解周期”明确为“保存后新建断面”，补齐等待、重试及历史结果的行为。
4. 明确原子保存、布尔值拒绝和配置持久化。
5. 接口路径、code及两个价格字段名沿用原MD，没有另造计算入口。
