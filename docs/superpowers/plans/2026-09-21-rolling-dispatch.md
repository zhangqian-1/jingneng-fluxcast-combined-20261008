# 七站滚动调度实施计划

> 2026-09-22变更：下文为首次实施记录。最新需求取消燃机预测必填；实际状态、未来需求、风光可用预测必填，原计划仅可选比较。变更实施与验证见[../../rolling-verification-20260922.md](../../rolling-verification-20260922.md)。

用户已明确要求直接修改代码和材料。执行方式：当前任务内实施，不另开任务、不修改其他人的算法。

目标：七站和19个风光场站每15分钟上传实际值；预测走独立接口；内部前视8步（2小时），每轮仅发布1步建议。缺少预测返回等待状态，不用实测或旧文件伪造预测。

## 文件职责与任务

- [x] `src/rolling_models.py`：严格输入模型，实际与预测分开，统一UTC；分别校验7站、19站、8步15分钟时间轴。
- [x] `src/rolling_store.py`：SQLite保存实际快照、预测版本和计算结果；重复请求幂等，禁止旧结果覆盖新结果。
- [x] `src/rolling_service.py`：数据到齐后触发计算，状态/时间检查、错误日志、仅返回首步建议。缺预测或状态不齐时返回明确等待原因。
- [x] `src/rolling_solver.py`及`src/highs_solver.py`：复用成本与功率平衡模型，支持8步前视、实际初始状态、剩余开停机时长和按运行日累计启停次数；不静默夹紧实际初值，不生成离线图片。
- [x] `api.py`：实际上报、燃机预测、风光预测、供电需求预测和状态查询端点；与现有自然日96点接口明确区分。
- [x] `tests/test_rolling_api.py`、`tests/test_rolling_solver.py`：先复现未实现，再验证等待预测、实际/预测隔离、8步前视1步发布、下一断面更新、重复与晚到数据、跨日及初始约束。
- [x] `docs/rolling-api.md`、`README.md`、`data/README.md`、示例请求：说明现有输入的实际数据角色，预测接口待外部接入；历史96点端点保留为历史兼容，不能称作新实时滚动功能。

## 数据边界

用户已确认：未来需求由独立的平台总负荷预测/供电计划输入。实际功率决定初始状态，不用七站预测合计代替总需求。保留燃机未优化预测作为基准核算必填输入，风光可用功率预测另行上报。最终采用8步前视、1步发布，未改成单断面独立求解。

首次运行若缺少已运行/停机时长与当日启停次数，不凭空假设为0。真实上报缺少这些字段可以存储，但不能将状态不完整的结果标作可执行调度建议。
