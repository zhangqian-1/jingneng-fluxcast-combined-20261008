# 一个请求返回优化与当天预测

依据用户最新确认：一个容器、一个对外端口、一个 compute 请求；全天预测每天返回一批，界面显示北京时间当天 0—24 点。用户已撤销 08:30 限制，本版没有固定钟点发布条件。

## 请求与返回

仍调用 `POST /api/v1/fluxcast/compute`，默认宿主机端口 18768。三个输入字段 `point_table`、`frames`、`renewable_data` 不变。`frames` 为 UTC 连续 96 帧历史，末帧当前。平台不再另外调用 18780，也不需要访问容器内部 8001/8002。

成功优化保留原54个数值点和8个字符串点，r7新增[界面直接返回字段](界面变量直接返回-20261001.md)。响应点数随当日曲线长度和有效性变化；当天完整预测可用且尚未发布时，在同一个result_point追加96个totalPowerForecastDayAhead点。其他响应不附带全天点，不表示应清空平台已保存的当天曲线。

| 变量 | 含义 | 时间 |
|---|---|---|
| totalPowerForecast | 本次优化实际采用的单点预测，原模型原值 | 下一 15 分钟目标时刻 |
| totalPowerForecastDayAhead | 同一原全天模型批次的 96 点七站合计功率预测，MW | 北京时间当天 00:00、00:15……23:45 |

不能按数组整体同一个时间绘图。平台按 varname 筛选全天点，再将 UTC 时间转北京时间并按 timestamp 排序。首点对应 00:00—00:15，末点对应 23:45—24:00；不再额外添加第 97 个“24:00”预测点。数值全部是有限浮点数，无 null、布尔值或占位零值。单点预测和全天预测不互相覆盖。

`extra_info` 仍保留供需平衡和七站计划状态原8个字符串点，并增加r7名称及状态字符串；`event_key` 仍是 `JNH.Fluxcast.Compute`。未就绪的优化返回 202 空数组；优化错误沿用原错误契约，不能单独返回全天点伪装成优化成功。

已有有效原计划比较时，另附baselineCostYuan和costSavingYuan两个数值点；无比较数据不填占位。详细新增字段见[数值补充约定](调度界面返回字段补充-20260929.md)。

## 自然日曲线来源与初始化

原全天模型是滚动 24 小时预测；没有修改原作者模型，也没有把上午生成的未来 24 小时曲线改名为当天预测。封装持续向两模型提供同一历史数据，遇到末帧为北京时间前一日 23:45 的有效输入时，将该模型输出的次日 00:00—23:45 完整 96 点保存为该自然日候选曲线。凌晨起的当天第一次有效成功请求可以发布它；生成时间和发布时间是不同概念。

没有拼接不同滚动批次、没有用当天实测填补已经过去的时段、没有使用未来数据反算过去。原模型禁止向在线缓存倒灌旧批次。20260929-r5在当天候选缺失时改用独立临时缓存自动补算：从当前缓存中截取零点以前的至少672点连续历史，原模型生成完整当天曲线后保存。漏掉日界线那次调用但后续滚动历史仍包含所需数据时可恢复；真实历史不足或天气未就绪时仍需补齐，不能虚构。见[自动补算说明](当天曲线补算及平台缓存-20260929.md)。

冷启动仍需补传真实历史：单点模型至少 288 点、全天模型至少 672 点；温湿度缺测可能需要更长历史。原 `/api/v1/fluxcast/forecast/compute` 初始化代理现在同时预热两模型，其 JSON 返回仍是原单点结果；初始化只保存自然日候选曲线，不消耗发布机会。按日期升序补传，末帧应覆盖北京时间各日 23:45；不得在包含更晚数据的缓存中倒灌旧批次。部署后没有当天候选曲线时会自动尝试用已有合格历史补算；历史本身不足则继续等待，不虚构当天数据。

## 一天一批、重试与持久化

SQLite 的 day_forecast_curve 保存候选，day_forecast_publication 保存发布日期、发布断面和完整返回点；均使用已有 /app/runtime 持久卷。发布日期取末帧的北京时间日期，并校验服务器日期，不用 UTC 日期直接分组。

一个自然日只由一个成功优化断面取得发布资格；同一断面重复请求重放同一批数据，供超时丢响应后恢复。平台按 `(varname,timestamp)` 幂等写入。其他时段不重复返回全天点。这里承诺唯一逻辑批次，不承诺 HTTP 响应网络传输恰好一次；没有另增确认接口。

重启保留候选及发布记录；并发使用 SQLite 事务竞争同一天发布资格。失败/等待不会占用发布记录；候选已存在时，即便滚动模型暂不可用，也可发布已校验并保存的当天候选。没有候选时，滚动预测不能替代自然日曲线。

## 可诊断状态

JSON 字段保持上述约定，响应头 `X-Fluxcast-Day-Forecast` 说明全天附加状态；工作日志保留同类记录。

| 状态 | 含义 |
|---|---|
| published / replayed | 当天批次首次返回 / 同一发布请求重试 |
| already_published | 当天另一个断面已发布，本次仅优化 |
| day_curve_missing | 缺少当天 00:00—23:45 整批；不使用滚动批次替代 |
| history_not_ready / weather_history_not_ready | 原模型历史尚未就绪 |
| unavailable / invalid_response | 原全天模型请求失败 / 返回未通过时间轴或数值校验 |
| recovery_history_not_ready / recovery_weather_history_not_ready | 零点前历史或天气不足，暂不能补算 |
| recovery_unavailable / recovery_invalid_response | 补算执行失败或结果校验失败，本次不发布全天曲线 |
| optimization_pending | 仅补历史或优化等待，不能发布 |
| outside_publication_day / future_observation | 日期或请求时间不适合发布 |

## 部署与显示边界

Compose 只映射 18768→8000；8001、8002 仅监听容器内回环地址。价格 GET/PUT 和展示页沿用同一端口，价格字段及求解目标不变。更新需重建或导入新版镜像并重建容器，源码上传不代表线上已更新。

仓库附带 dashboard 是离线历史情景演示，不是平台实时全天预测界面。本次改动提供上述当天曲线契约，平台前端需按变量名保存并显示，不将没有全天预测的响应理解为删除已保存的全天数据。

平台保存及跨日示例见[当天曲线补算及平台缓存](当天曲线补算及平台缓存-20260929.md)，不带96点的后续响应不能清空已保存的当天曲线。
