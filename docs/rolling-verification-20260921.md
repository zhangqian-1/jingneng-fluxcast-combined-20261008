# 滚动封装完成与验证记录

> 本文是2026-09-21版本的历史验证记录。2026-09-22已取消燃机预测必填，原计划改为可选比较输入；最新协议见[rolling-api.md](rolling-api.md)，本轮验证见[rolling-verification-20260922.md](rolling-verification-20260922.md)。以下旧版四类必填及基准约束说明不适用于新版滚动接口。

## 最终选择

用户确认保留预测前视方案：每15分钟接收实际断面，接收未来2小时8步预测，内部联合优化8步，对外仅发布下一步建议。当前没有改成单断面独立求解。

未来供电需求由独立平台总负荷预测/供电计划提供。实际值、燃机未优化预测、风光可用预测分别保存。现有数据文件不改写、不自动作预测兜底。燃机未优化预测当前用于成本/碳排放基准和购电分摊，仍是本实现的必要输入；不把它说成负荷预测或优化出力硬约束。

## 已实现

- 实际断面、燃机预测、风光预测、总需求预测四类上报端点和状态查询端点，字段见[rolling-api.md](rolling-api.md)。
- SQLite输入与结果持久化，输入修订历史、并发重试幂等、旧断面拒绝、新结果版本和过期判断。
- 数据/状态未齐返回waiting_inputs；无法求解返回failed并记日志，可在未发布前修订预测重算。
- 继承实际初始功率和开停机历史，按运行日累计次数，处理跨午夜与剩余最小开停机时间。
- 独立求解进程，20秒HiGHS限时、25秒进程限时；只返回首步27个功率值，内部8步保存作审计，不生成离线图片。
- 首步step_metrics与2小时horizon_metrics分开，防止重叠窗口合计重复累计。
- README、配置样例、数据说明、历史协议标识、完整请求生成脚本已同步。

## 验证

- 全量回归：**222 passed in 39.11s**。
- 滚动相关：26项，包括实际/预测隔离、缺预测等待、8步时间轴、独立需求平衡、首步费用/电量、初始状态约束、跨日预算、输入修订、过期结果、失败状态和并发幂等。
- 特别验证：在当前实际状态和第一时段需求相同的情况下，改变未来需求会改变首步出力；说明后续预测通过爬坡约束参与本轮决策。
- Ruff检查通过，73个Python文件格式通过。
- 原28份输入清单与哈希校验通过：7 CSV、19 JSON、2 Excel，共66,046,581字节；ARM依赖wheel清单检查通过，未在ARM设备实际运行。
- 独立HTTP联调采用明确标识的人工数据及模拟时钟，调用真实HiGHS进程。四次上报状态依次202、202、202、200；返回27个功率值、1个时间戳，满足250 MW需求；首步计划电量62.5 MWh。
- 联调结果路径：`output/rolling-verification-20260921/7d7bfeed/`，包含四类请求、response.json、verification.json、SQLite和工作日志。人工数据不是现场实际验收数据。

## 尚未完成的外部条件与模型边界

1. 实际上报方和三个预测来源仍待平台接入；接口就绪不代表真实预测已接通。实际状态持续时长与计数必须由可靠来源提供。
2. 2小时模型可继承已有开停机义务，但尚未接入全天启停计划，无法保证窗口外的全部经济性和可行性；仍为调度建议，没有自动控制下发。
3. 只购电基准要求燃机参考预测合计不超过总需求；更复杂的基准修正暂未增加。购电上限与分摊沿用原模型假设。
4. 老看板仍是96点历史情景回放；数据库及日志没有自动清理策略。
5. 本次没有提交/推送远端，没有部署服务器，也没有变更别人负责的预测算法。
