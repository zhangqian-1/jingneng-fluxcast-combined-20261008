# 96点预测与实测逐字段对接说明

更新日期：2026-10-09。本文对应已发布联合包 `20261008-r37750002283a1`，运行代码提交 `3d2782ffafd6d92f379e34e61383d556b28c0b89`。本次仅补充文档，不更改算法、接口或镜像。

本文完整列出新版96点预测及其配套实测返回，不展开调度和单点预测字段。联合响应中仍有其他模块的结果，平台应按字段名、时间读取，不按数组位置或数组总长度读取。

## 1. 调用入口与输入

平台继续调用 `POST /api/v1/fluxcast/compute`，默认地址 `http://127.0.0.1:18768/api/v1/fluxcast/compute`，请求头 `Content-Type: application/json`。本次没有新增平台必填字段，也没有在联合服务公开单独的实测提交接口。96点服务在容器内部的8002端口不对外发布。

| 输入字段 | 类型 | 96点功能相关要求 |
|---|---|---|
| `point_table` | 字符串数组 | 沿用原35个模型测点；完整清单见 [测点配置](../config/forecast_measurement_points.json) 和 [测点表](forecast-measurement-points.csv)。不能缩减成下面19个功率点 |
| `frames` | 对象数组 | 恰好96帧，连续升序，每15分钟一帧；末帧时间记作 t。每帧含 `timestamp` 和测点值 |
| `frames[].timestamp` | 时间字符串 | 推荐UTC，如 `2026-10-08T00:30:00Z`。无时区字符串也按UTC解释；带时区输入会转为UTC。须整15分钟对齐 |
| `frames[].<测点编码>` | 数值或 `null` | 功率单位MW；缺测建议明确传 `null`。实测统计只取末帧中的19个原始功率值 |
| `renewable_data` | 对象数组 | 保留原联合接口输入约定。96点配套实测统计不读取此字段；本次不改变其接口要求 |

原测点名中的点号 `.` 可按既有规则改成下划线 `_`，冒号 `:` 保留；同一帧不能同时提供原名和转义名。返回的 `missingPoints` 使用下表原始编码。

下面19点用于实测统计，原35点中的气象等其他输入仍用于预测。各站实测是该站有效功率点经负值归零后的求和，不是平均值。

| 站编码 | 应有点数 | 原始功率测点（MW） |
|---|---:|---|
| GARD | 3 | `GARD_11MBY0100000BJ01XQ01`<br>`GARD_12MBY0100000BJ01XQ01`<br>`GARD_13MKA01CE903BJ01XQ01` |
| JXRD | 5 | `JXRD_11MBY0100000BJ01XQ01`<br>`JXRD_12MBY0100000BJ01XQ01`<br>`JXRD_13MKA01GA001BJ02XQ01`<br>`JXRD_14MBY0100000BJ01XQ01`<br>`JXRD_15MKA01GA001BJ02XQ01` |
| JYRD | 3 | `JYRD_LOADCTL:GTMWSEL1_1.OUT`<br>`JYRD_LOADCTL:GTMWSEL1_2.OUT`<br>`JYRD_30DCS01:FU101.PNT` |
| JQRD | 3 | `JQRD_10CBA00FA107XQ93`<br>`JQRD_10CBA00FA108XQ93`<br>`JQRD_10CBA00FA109XQ93` |
| JFRD | 1 | `JFRD_11MKA01GA001BJ40XQ01` |

96帧是每次请求窗口；96点模型冷启动仍需要至少672个连续可用历史点及足够天气上下文。不能把“输入96帧”理解为“首次请求即可产生96点预测”。

## 2. 响应结构与时间

成功或等待响应仍以原联合接口为准，以下结构只展示字段形状：

```json
{
  "event_key": "JNH.Fluxcast.Compute",
  "result_point": [
    {"varname": "totalPowerActual", "timestamp": "2026-10-08T00:30:00Z", "value": 190.0}
  ],
  "extra_info": [
    {"varname": "dataStatus", "timestamp": "2026-10-08T00:30:00Z", "value": "complete"}
  ]
}
```

| 字段 | 类型 | 规则 |
|---|---|---|
| `event_key` | 字符串 | 固定 `JNH.Fluxcast.Compute` |
| `result_point` | 数组 | 数值条目；`value` 是有限JSON数值，计数也按浮点数返回，例如 `96.0` |
| `extra_info` | 数组 | 文本条目；`value` 是字符串，不是对象或数组 |
| 两数组内的 `varname` | 字符串 | 本文表格列出的精确字段名，区分大小写 |
| 两数组内的 `timestamp` | 字符串 | 该条结果的时间，均表达UTC；外观尽量沿用请求末帧的分隔符、时区后缀和小数格式 |
| 两数组内的 `value` | 数值或字符串 | 类型由所属数组决定；不能计算的数值条目通常直接省略，不返回 `null`、空字符串或占位0 |

本文使用三个时间标记：**q**为曲线某一目标时刻，**g**为该批预测实际生成时间，**t**为请求末帧实测时间。不同结果不能仅按数组顺序配对。

`forecastGeneratedAt`、`forecastStartAt`、`forecastEndAt` 的字符串值保持上游UTC写法；`latestActualAt` 的字符串值使用内部规范化UTC写法，可能没有 `Z`。外层 `timestamp` 的格式转换不会改写这些字符串值，应按UTC解析。

当天曲线按北京时间00:00、00:15、…、23:45排列。例如北京时间2026-10-08当天，对应UTC `2026-10-07T16:00:00Z` 至 `2026-10-08T15:45:00Z`。共96点，相邻15分钟；最后一个时间标签是23:45，不能把 `forecastEndAt` 改成次日00:00。

## 3. 全局数值字段（result_point）

| 精确字段名 | 含义 / 单位 | 时间 | 返回条件 |
|---|---|---|---|
| `totalPowerForecastDayAhead` | 七站合计发电功率预测，MW；完整批次96条 | 每点q | 当天首次发布，或重试首次发布所对应的同一末帧时间。当天其他请求不重复携带曲线 |
| `forecastPointCount` | 预测点数，固定 `96.0` | g | 发布或重放时有可信新版来源元数据，返回1条 |
| `forecastIntervalMinutes` | 预测间隔，固定 `15.0` 分钟 | g | 同上 |
| `totalPowerActual` | 七站19点归零后实测合计，MW | t | 19点全部有效且合计有限；全部为零时返回 `0.0` |
| `totalPowerDeviation` | 同刻预测减实测，MW | t | 实测合计可计算，存在符合时间条件的固定批次同刻预测，且差值有限 |

`totalPowerDeviation > 0` 表示预测高于实测，`< 0` 表示预测低于实测。它不是百分比，也不是实测减预测。

上游独立96点程序的曲线字段为 `totalPowerForecast`，联合接口将这96条改名为 `totalPowerForecastDayAhead`。平台不能把联合响应里的 `totalPowerForecast` 当作96点曲线；该名称留给既有单点结果。

## 4. 全局文本字段（extra_info）

| 精确字段名 | 含义 / 值 | 时间 | 返回条件 |
|---|---|---|---|
| `forecastBatchId` | 预测批次号，`dayahead-` 加32位小写十六进制字符 | g或t | 发布/重放元数据时在g返回；成功计算实测偏差且有关联公开批次号时在t再次返回 |
| `forecastGeneratedAt` | 固定批次的实际生成时间，UTC字符串 | g | 发布或重放且有来源元数据；不是本次请求时间，也不是强行回填的零点时间 |
| `forecastStartAt` | 曲线首点UTC时间 | g | 同上 |
| `forecastEndAt` | 曲线末点UTC时间 | g | 同上 |
| `dataStatus` | 19个实测点有效性：`complete` / `incomplete` / `missing` | t | 每次执行到实测追加步骤时返回 |
| `missingPoints` | 全部缺失/无效功率点原始编码，用英文逗号连接，无空格 | t | 至少一个实测点无效；不是JSON数组 |
| `reason` | 实测结果省略的主原因，见第6节 | t | 存在缺测、无匹配预测、零合计或数值范围问题 |
| `message` | 诊断详情，含原因、相关输入和被省略的字段；多项用 ` | ` 连接 | t | 有诊断原因时返回。供显示/排查，不建议解析自然文本驱动业务 |
| `latestActualAt` | 已保存且可计算七站总实测的最新目标时间，UTC字符串 | t | 数据库内至少存在一条可计算总实测，包括本次；当前缺测时可能指向较早记录，历史请求时也可能晚于t |

同一响应可能有两条 `forecastBatchId`：g时刻说明曲线批次，t时刻说明偏差关联批次。请按 **(`varname`, `timestamp`)** 读取，不能只按字段名覆盖成一个字典。`forecastBatchId` 在实测条目中缺席不代表没有曲线，也可能是本次无法计算偏差。

`dataStatus=complete` 只代表19个输入都有效，不保证有匹配预测；极端数值求和溢出时也可能仍为 `complete`，需同时判断目标数值条目是否存在。

## 6. 状态、原因与省略规则

### 6.1 数据完整性

| 值 | 全局含义 | 站级含义 |
|---|---|---|
| `complete` | 19点全部有效 | 本站必需点全部有效 |
| `incomplete` | 部分点有效、部分无效 | 本站部分有效、部分无效 |
| `missing` | 19点全部无效 | 本站必需点全部无效 |

每个功率点先独立执行 `max(0, 原值)` 再求和。例如本站有-5与10，实测为10，不是5。缺测不补0、不用历史前填值或预测值替代。数值字符串 `"10"`、布尔值 `true`、`null`、缺字段都不是有效功率值。

### 6.2 reason枚举

| `reason` | 触发条件 | 主要省略项 |
|---|---|---|
| `missing_power_points` | 至少一个末帧功率点无效 | 受影响站 `powerActual`、七站合计、总偏差、全部站占比；其他完整站的实测和全部计数继续返回 |
| `no_matching_forecast` | 总实测可计算，但没有符合条件的同刻预测 | 只省略总偏差及其批次条目；正合计时仍有站占比 |
| `total_power_zero` | 实测合计为0 | 所有站占比；总实测及各站实测仍为0，有有效预测时偏差仍可计算 |
| `power_sum_out_of_range` | 各输入有限但总和/站和不可表示为有限数值 | 对应的合计、受影响站实测及相关偏差/占比；完整性状态仍可能为complete |
| `deviation_out_of_range` | 预测减实测不是有限数值 | 总偏差及其批次条目；其他可计算字段保留。当前非负预测和实测约束下通常不会触发，保留为代码中的保护分支 |

多个问题可以同时存在，但全局 `reason` 只有一个：有缺测优先 `missing_power_points`，否则取诊断列表第一项。例如“合计0且没有匹配预测”时，reason为 `no_matching_forecast`，message同时包含 `total_power_zero`。不能仅凭一个reason判断全部省略项。

`message` 中的无效输入细分包括：`missing_field`（缺字段）、`null`、`invalid_type(bool)`、`invalid_type(str)`等类型名、`nonfinite`、`numeric_overflow`。标准JSON不允许NaN/Infinity，联合请求验证会拒绝非有限JSON值；不要为触发这些内部诊断发送非法JSON。`diagnostics`、`causes`、`omitted` 不是新增响应顶层字段，结构化诊断保存在日志中。

### 6.3 HTTP与当天曲线状态头

当天曲线是否返回通过响应头 **`X-Fluxcast-Day-Forecast`** 表达，不是 `extra_info` 中的字段。`Cache-Control` 为 `no-store`；平台须自行保存已收到的当天曲线。

| 状态头值 | 含义 / 平台处理 |
|---|---|
| `published` | 首次发布当天完整96点；保存曲线及其批次元数据 |
| `replayed` | 重试首次发布所对应的末帧时间，重放原曲线；按同一天/批次幂等保存 |
| `already_published` | 当天已由另一末帧时间的请求发布，本次不附带96点；继续使用平台已保存曲线 |
| `optimization_pending` | 联合入口未满足发布成功条件（例如HTTP不是200，或首帧功率不可用）；不附带曲线。此名字是现有状态名 |
| `outside_publication_day` | 请求末帧北京时间日期不是服务当前北京时间日期；不发布该历史/其他日期曲线 |
| `future_observation` | 请求末帧时间晚于当前服务时钟；不发布 |
| `day_curve_missing` | 模型有滚动结果，但没有可发布的当天自然日完整曲线 |
| `history_not_ready` / `weather_history_not_ready` | 模型功率/天气历史未就绪 |
| `unavailable` / `invalid_response` | 96点上游不可用/响应不符合约定 |
| `recovery_history_not_ready` / `recovery_weather_history_not_ready` | 当天曲线补算所需历史/天气不足 |
| `recovery_unavailable` / `recovery_invalid_response` | 当天曲线补算服务不可用/结果校验失败 |
| `disabled` | 96点客户端未启用，主要用于隔离测试；此时不追加本文实测结果 |

内部还会记录 `ready`、`recovered`、`input_unusable` 等模型状态；它们不是新增文本字段。判断前端是否拿到曲线，仍以状态头和实际96个曲线条目为准。

实测追加不以“本次是否返回曲线”为条件：只要启用96点客户端且请求执行到追加步骤，就会统计末帧，包括正常、部分返回，以及到达该步骤的HTTP 202等待响应。请求格式校验失败、未被转换为部分返回的服务异常等会提前退出，不能保证这些错误响应包含本文字段。HTTP 200也不保证偏差、占比等条件字段齐全。

## 7. 发布、偏差与平台缓存

1. 当前没有独立定时任务，也没有固定08:30门槛。请求触发历史更新及模型调用；“每天固定发布一批曲线”不等于“模型一天只运行一次”。
2. 首次发布须已有合法当天00:00—23:45候选、接口走到发布步骤且返回状态200、输入首帧19个功率点通过既有可用性检查、末帧属于服务当前北京时间当天且不在未来。部分返回若满足相同条件也可发布。首次发布请求原样重试可以重放；后续不同末帧不附带整条曲线。
3. 曲线优先来自零点前最后时段的预测；若缺失，使用零点前足够真实历史在隔离缓存补算。模型历史不足时等待，不用不同滚动批次拼96点。
4. 平台按北京时间日期及批次保存96点；`already_published`不等于空曲线，应保留当天已存曲线。跨日应切换日期，不能把昨天的曲线当成今天。`forecast/latest`是原辅助接口，不能当成本文固定96点曲线查询接口。
5. 偏差要求同一个UTC目标时间t，并使用已固定、已发布曲线来源。来源的首次保存时间和实际生成时间必须都**严格早于t**。晚补算的曲线可以展示，但不能事后制造其保存/生成以前的偏差。
6. 同刻实测已有批次关联时，后续接收仍使用该关联。旧曲线没有可信来源元数据时可以继续展示，但不会伪造批次与偏差。联合入口原有的同断面冲突校验仍有效，不能据此假定任意改写历史请求都被允许。
7. `latestActualAt`表示最新可计算总实测时间，不表示本次一定完整，也不是最新预测时间。当前条目缺席不能用旧值填成当前时刻的有效值。

## 9. 字段覆盖与部署索引

本文覆盖**63个不同字段名**：33个数值名（含1个曲线名、2个预测统计、2个总实测/偏差、28个站级数值）与30个文本名（9个全局、21个站级）。这是字段名字典数量，不是每次返回条目数；曲线名重复96次，批次名可在两个时刻出现，条件字段可省略。

正常发布且匹配偏差、各站均有效、总实测大于0时，本模块贡献128个数值条目、14个文本条目。其他模块还会追加各自结果，因此不能校验整个联合数组必须等于这些数量。

当前封装为Linux AMD64，一个联合镜像、一个容器。升级使用新的 `day_ahead_forecast_runtime_20261008` 历史卷，须重新补传预测历史；旧96点历史卷不能改名冒用。实测关联记录随 `/app/runtime` 持久化。完整部署背景见 [96点新版接入说明](96点新版接入-20261008.md)。

代码核对依据：`api.py`、`src/platform_adapter.py`、`src/day_forecast_publication.py`、`src/day_observations.py`、`src/vendor/dayahead/result_contract.py`、`src/vendor/dayahead/contract.py`、`src/vendor/dayahead/storage.py`。本说明的字段、条件和示例对应上述发布版本；历史说明与本文涉及96点新增字段的表述有冲突时，以本文和当前发布代码为准。
