## 仍需落实的事项

1. **平台接入及批次规则。** 当前可接收原生长表，但不会主动轮询报告中的GET接口或自动选取上一发布批次；平台需完成取数、透传及批次选择。当前随包预测仅覆盖9月19日至28日，后续日期必须提供新预测。相同时间轴的已完成批次拒绝不同输入覆盖；如果需要同日更换预测重算，应另行约定修订批次机制。
2. **空结果兼容。** 算法端null路径已测试，接收平台仍需验证能识别unavailable，不能把null当0或执行为空的指令。HTTP200不单独代表计算成功。
3. **看板更新。** 页面读取保存的结果；刷新只重新读取文件。七站接口计算结果位于各批次运行目录，不会自动覆盖output/final；查看新批次需配置DASHBOARD_RESULT_DIR或明确发布展示结果。公网展示与目标服务本次均未更新。
4. **目标环境验收。** 依赖wheel存在不等于Kylin ARM主机已成功运行，仍需验证容器/运行时、日志与输出目录权限、实际七站请求及求解耗时。
5. **调度模型适用范围。** 当前负荷取七站原出力之和，基准保持该原出力，因此基准新能源接纳为零，是比较情景；综合成本含弃电惩罚，节约额不能直接等同实际现金节约。购电能力采用峰值负荷20%的参数，尚未表示实际联络线；模型为场站级，未覆盖站内机组分配、供热及潮流，也未完整表示跨日剩余最小开停时间。当前适用于约定情景下的调度辅助分析。
