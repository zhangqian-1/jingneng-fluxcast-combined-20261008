# 滚动调度展示更新

## 展示口径

- 保持原单页布局、配色、五张指标卡、七站顺序和新能源独立放大功能。
- 每轮显示连续8个15分钟计划时段。默认选中首步，其余7步标为前瞻参考。
- 当前实测来自本轮实际输入；切换未来计划时段不会改变当前实测值。
- 首步调整为首步优化出力减当前实测。后续时段不显示实时调整量。
- 指标卡、分析和成本明细累计本轮起点至所选时段，包含该时段。电量为功率乘0.25小时后求和。不同滚动窗口存在重叠，不将各轮预测累计重复相加。
- 原调度计划是可选比较数据。缺少有效原计划时显示“—”，不构造成本节省或减碳量。
- 接口、时间轴、数据时间均按UTC展示。

## 数据接口

新增只读接口 `GET /api/v1/fluxcast/rolling/dashboard`，从 `ROLLING_DB_PATH` 指定的SQLite存档读取最新完成批次，返回 `displayOnly: true` 的展示数据。

该接口包含8步参考计划和逐时段核算信息，不返回执行接口的 `result_point`，不改变原首步发布接口。导出CSV也标注为前瞻参考，并通过 `is_published_step` 标识首步。

接口尚无完成结果时返回 `waiting_inputs`；读取失败返回503。新断面尚未完成时将上一批次标为 `superseded`；超过有效期显示历史参考。

页面每30秒检查一次。手动浏览后续时段或播放期间保留当前显示；返回首步后恢复检查。新批次到达时整体更新8步计划，并选中首步。已有实际计算结果后，更新失败保留旧结果并显示提示，不替换为演示数据。

## 演示与现场数据

没有可读取的真实滚动结果时，本地与静态网站使用 `rolling-data.json` 进行演示。该文件由 `examples/build_rolling_dashboard_demo.py` 调用真实HiGHS求解器生成，输入是人工联调数据，页面明确标注“滚动优化演示 · 非现场数据”。

静态文件本身不具备接收现场上报和求解能力。在线实时展示需要部署滚动服务，并将同域 `/api/v1/fluxcast/rolling/dashboard` 路由到该服务。
