# 96点新版接入说明

本次以同学已更新调度的 develop 工程为基础，接入96点预测发布版本 `v7station-platform-4a38c670cfcf`。单点预测镜像、调度算法、输入预处理和调度结果计算代码均保持原版；不重新训练模型。

## 已确认规则

- 保留北京时间当天00:00至23:45曲线，对外仍使用 `totalPowerForecastDayAhead`，避免与下一15分钟的 `totalPowerForecast` 混淆。
- 保留原预测调用频率。每天发布一次曲线不等于每天只推理一次；本次未新增只更新历史的接口。
- 偏差只对应已经保存并发布的同一批当天曲线，取相同UTC时刻的预测减实测。
- 实测使用原请求末帧19个原始功率测点，复用新版负值归零、缺测、站级统计与偏差规则，不使用调度前填或预测补零后的数据。
- 调度失败仍遵循原错误状态；本次不把失败改成成功。原调度部分返回逻辑不改。

## 新增返回

平台继续调用 `POST /api/v1/fluxcast/compute`。原请求结构和单点到调度链路不变。

发布或重放当天96点曲线时，额外返回 `forecastPointCount`、`forecastIntervalMinutes`，以及 `forecastBatchId`、`forecastGeneratedAt`、`forecastStartAt`、`forecastEndAt`。统计和批次属于这批固定曲线，不是本次滚动预测。字符串时间值保留上游UTC表示，条目 timestamp 跟随平台输入时间格式。

在原接口正常或部分返回时追加：`totalPowerActual`、可计算时的 `totalPowerDeviation`、七站 `*_powerActual`、`*_powerShare`、`*_validPointCount`、`*_requiredPointCount`，以及数据完整性、缺测和原因说明。条件与新版独立实测服务一致。七站全0时合计为0，不返回除零占比；缺测仅省略受影响结果。

调度方已有的 `*_actualMW` 与本次新增 `*_powerActual` 是不同的既有接口字段，均保留，不重命名、不覆盖。不得用响应数组总长度识别96点曲线，应按 varname 筛选。

## 批次与持久化

联合数据库新增 `day_forecast_source` 表，保存固定曲线的原响应、真实批次和首次接收时间，与曲线同一事务写入。已存在的旧曲线没有来源元数据时不伪造批次；可以继续展示，但没有可信同刻预测时不返回偏差。

实测存储使用联合数据库同目录下的 `*-day-observations.sqlite3`，随已有 `/app/runtime` 卷持久化，独立于调度数据表。重试、重启和实测修正仍使用原关联批次。当天补算的曲线只可用于生成且保存之后的目标时刻，不能事后补出过去时刻的预测偏差。

## 部署版本

96点镜像固定为 `ghcr.io/zhangqian-1/jingneng-power-forecast-observations-20261008@sha256:e22497c10e43e1204c1fe952080e1931750af3d10b514a0727f6a7e04f8e013a`，来源记录见 `deploy/forecast-dispatch/vendor-day-release.json`。

新版功率处理规则要求新的预测历史卷。Compose 使用 `day_ahead_forecast_runtime_20261008`，保留旧卷、单点卷和调度卷；须重新补传至少672个连续可用历史点。不能将旧预测缓存改名当成新版缓存。

在有可运行Docker的Linux AMD64环境中构建：

```powershell
docker compose --env-file deploy/forecast-dispatch/.env.example -f deploy/forecast-dispatch/compose.yaml build
```

本地源码测试通过不等于镜像构建或目标服务器联调通过。本项目在 GitHub Actions 中完成真实预测、调度、实测返回、原模型与依赖、重启持久化及导出后离线启动验证；全部通过后才发布 Release。下载地址为 https://github.com/zhangqian-1/jingneng-fluxcast-combined-20261008/releases ，验证证据随 Release 提供。目标平台服务器验收仍需单独完成。

两套预测分别保留原始镜像中的 Python 解释器、标准库、依赖和模型：单点为 Python 3.11.16，新版96点为 Python 3.11.17。封装不会让新版96点共用旧解释器。容器对外仍只有一个接口端口。
