# 当天曲线自动补算与平台缓存

## 本次修复

20260929-r5在r4的一个容器、一个端口、一个compute请求基础上，修复“漏掉日界线请求就无法自动恢复当天曲线”的限制。当天曲线缺失时，封装自动读取原全天模型的历史缓存快照，截取北京时间当天00:00以前的数据，用独立临时缓存调用原模型。校验结果覆盖当天00:00—23:45连续96点后，写入已有候选表。

每天第一次优化成功且候选有效时，向同一result_point附带96个totalPowerForecastDayAhead点，共126个数值点；其他成功时段仅30个数值点，8个extra_info字符串点保持不变。没有08:30限制，也没有增加业务接口路径、容器或对外端口。相同发布请求重试重放同一批，平台应幂等保存。

## 补算边界

- 补算不修改原预测代码/模型及在线缓存，不改变单点预测驱动优化的方式。临时工作目录由父进程回收，子进程超时或失败也清理。
- 仅使用预测日零点之前的历史，原始缓存中属于当天的实测行全部剔除。缺测值仍作为缺测交给原模型处理，不人工插值、不把实测拼到预测曲线中。
- 必须仍保留截至前日23:45的至少672个连续历史点和原模型需要的天气/状态上下文。缓存不足、时间缺行、真实历史缺失或天气尚未就绪时仍不能保证生成；需补齐真实历史并正确初始化，不能无数据补预测。
- 补算在优化时效检查之前完成，避免慢补算让已经计算好的调度建议过期后仍被发布。每次补算最多等待45秒；失败不写发布记录，后续有效请求仍可重试。
- 已保存的候选和发布批次不覆盖。重启保留已有SQLite记录；补算成功后同一天不再重新运行补算。

正常发布仍使用published/replayed/already_published响应头状态。失败时新增可诊断状态：recovery_history_not_ready、recovery_weather_history_not_ready、recovery_unavailable、recovery_invalid_response。JSON顶层字段保持不变。工作日志记录补算日期、历史截止时刻、可用历史点数和被排除的未来数据行数。

## 平台如何保存曲线

提供无需额外依赖的JavaScript示例 [daily-forecast-cache.mjs](../examples/daily-forecast-cache.mjs)：

```javascript
import {mergeDailyForecast, currentDayCurve} from './daily-forecast-cache.mjs';

// 正式系统建议在平台后端持久保存；这里用浏览器存储演示。
let cache = JSON.parse(localStorage.getItem('fluxcastDailyCurves') || '{}');
cache = mergeDailyForecast(cache, responseBody);
localStorage.setItem('fluxcastDailyCurves', JSON.stringify(cache));
const todayPoints = currentDayCurve(cache);
// todayPoints为空时显示“当天预测待生成”，不要拿昨天曲线冒充今天。
// 非空时按timestamp转北京时间显示00:00—24:00，末点是23:45时段。
```

1. 单独筛选totalPowerForecastDayAhead，校验96个完整时间点后，按北京时间日期整体保存。
2. 收到普通30点响应、等待空数组或不带全天变量时，不删除已保存的当天曲线。
3. 同一批次重试覆盖相同的时间键，不追加重复点。跨日只显示当天数据；昨天仍可作为历史查询。
4. 不完整批次或非法数值拒绝覆盖现有有效曲线。异常应在平台显式提示，不作为“清空”操作。

示例检查命令：`node scripts/check_daily_forecast_cache.mjs`，覆盖9项保存/重试/跨日/非法批次场景。此文件是供平台接入的示例，平台前端代码不在本仓库，本次没有修改或部署线上平台界面。

## 验证依据

单元测试覆盖672点历史截断、排除当天数据、缺行/乱序/重复时间拒绝、真实null保留、子进程超时和临时目录失败、补算错误轴及数值拒绝、每日一次与重启重试。

真实容器回放25天历史，在隔离HTTP测试的候选表为空时自动恢复当天曲线。补算96点与原模型已生成批次逐点相同；对原历史缓存和latest文件做补算前后哈希核对，确认没有变化。原两套模型文件和依赖也保持一致。新能源输入为明确的测试情景，不能据此声称现场闭环完成。
