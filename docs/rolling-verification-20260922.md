# 滚动封装变更与验证记录（2026-09-22）

## 用户确认的输入边界

必需：实际运行状态、未来负荷/供电计划、风光可用功率预测。可选：原调度计划，仅用于优化前后成本和碳排放比较。

已有现场出力按实际数据使用；实际出力是已发生的测量，原调度计划是对未来时段的安排，两者不互相替代。每15分钟更新实际断面，前视2小时8步，仅发布下一步建议的机制保留。

## 本次改动

1. 取消滚动接口的燃机预测必填及其旧端点；新增可选`POST /api/v1/fluxcast/rolling/reference-plan`，完整字段见[rolling-api.md](rolling-api.md)。默认联调示例仅生成3份必要请求，可用`--include-reference-plan`另生成原计划。
2. 滚动求解不再依赖基准构建或基准碳排放上限，碳排放成本仍计入目标。旧96点模式保留原有基准约束。
3. 为避免原计划影响优化，站间购电费用分摊权重改由本轮实际燃机出力占比确定，窗口内固定；全为0时等比分摊。此为当前结算建模假设，尚不代表平台实际结算规则。比较核算复用相同权重。
4. 没有原计划时返回`comparison.status=not_provided`，保留优化后的成本、碳排放和电量，不虚构基准或节省量。
5. 原计划比较采用同一需求、风光可用上限、价格、排放系数与实际初始状态。原计划不满足同口径条件时，仅比较不可用并记录原因，不阻断优化。
6. 有效结果生成后可补交原计划，直接对归档结果核算，不重新求解、不改变出力建议和生成时间。计划及比较结果持久化；重复提交幂等，冲突内容不覆盖。
7. README、接口文档、数据说明、配置注释、示例生成脚本同步；旧实施和验证材料标注为历史记录。原始数据文件及其他人的预测算法未因本轮修改而变更。

## 二次检查及修复

本轮复查先用失败测试确认了以下缺口，再修改实现：

1. 启停历史：相同状态的持续时间被重置时，原来可能漏计中间启停循环；中间缺报状态也可能跳过上一完整记录；首次上报可能遗漏当日可观测切换。现已补齐核对，并验证合法启停循环和运行日跨午夜重置不会被误拒绝。
2. 发布时限：原来只检查求解完成时间，比较核算跨过生效时刻后仍可能发布。现在核算后再次检查；补交比较完成时结果已到期，也不返回过期指令。
3. 日期边界：极端日期在时区换算或构建8步窗口时会触发未处理溢出并返回500。现改为明确的422输入校验错误。
4. 模型文档增加历史96点与8步滚动模式的区分，避免把等效负荷与独立总需求、基准碳约束和可选比较混用。

新增10项回归用例；全量结果为 **239 passed in 46.87s**。Ruff检查通过，76个Python文件格式检查通过。运行中服务核查：本机127.0.0.1的8768、8000、8769端口均拒绝连接，因此不能声称原网址目前已运行新版服务；本轮没有据此改变远端部署。
